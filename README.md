# KIU DevOps Infrastructure Project

This project provisions a full infrastructure stack on AWS Cloud, designed for deploying containerized applications using Kubernetes (EKS), PostgreSQL (Aurora RDS), and other essential services, such as Cluster Autoscaler, NGINX Ingress Controller and Cert Manager. Infrastructure is managed with Terraform, and application deployment is handled with Helm.

## Infrastructure Overview

### Network
Creates a VPC with public and private subnets across availability zones, and a NAT Gateway to allow internet access for private subnets.

### RDS Aurora (PostgreSQL)
Provisioning a High Availability Aurora PostgreSQL Cluster, supporting:
- Auto-scaling with read replicas
- Daily backups with increased retention
- Encrypted storage
- Deletion protection
- Secrets managed via AWS Secrets Manager
- Private access through VPC Security Groups
- CloudWatch logs export

Security Best Practices:
- Passwords autogenerated and stored securely
- No public access
- Monitoring enabled via CloudWatch

Technical Debt:
Add CloudWatch alarms for CPU and query performance thresholds.

### EKS Cluster (latest v1.31)
Deploys a Kubernetes cluster using Amazon EKS with managed node groups.

Key Features:
- Node group auto-scaling
- IRSA (IAM Roles for Service Accounts) for secure AWS access
- Modern EKS Access Entries (replacing aws-auth ConfigMap)
- Two IAM-based access levels:
  - Developer: Read-only in `default` namespace
  - DevOps: Cluster-wide edit permissions
- Secrets stored in AWS Secrets Manager mounted via CSI Secrets Store

Technical Notes:
- Modular and easily extensible, separated in AWS services.
- Currently designed for a single AWS account. (Dev/Stage/Prod separation recommended)

### NGINX Ingress Controller
Deployed via Helm, providing:
- Public access through AWS NLB (Network Load Balancer)
- (Optional) Prometheus metrics exporter support

### Cert Manager
Manages TLS certificates using Let’s Encrypt with ACME.

### Cluster Autoscaler
Controls the resources used by the running pods, and the requested by the control plane to create new or remove unneeded worker nodes of the cluster.

IAM permissions for autoscaler pods are granted through AmazonEKS_ASG_Policy via attached worker node roles. For enhanced security, we should consider using IRSA and granting access to a new assumable role to the Autoscaler service account.

## Cluster Technical Debt
This is out of the scope of this project, but necessary for Production environments:
- Pin ingress controller to dedicated nodes via node affinity
- Do the same with other deployed applications, separating concerns on different namespaces and nodes, based on workloads and priority
- Install Prometheus + Grafana for observability
- Add alerts for resource consumption or pod crash loops

## Deployment Guide

### Prerequisites
Ensure the following tools are installed and configured:
- terraform
- kubectl
- helm

You must have valid AWS credentials with permissions to provision infrastructure.

### Infrastructure Deployment

```bash
cd ./infra
terraform init
terraform plan
terraform apply
```

After deployment, configure kubectl to use the new EKS cluster context.

### Install CSI Secrets Store

```bash
helm repo add secrets-store-csi-driver https://kubernetes-sigs.github.io/secrets-store-csi-driver/charts
helm install csi-secrets-store secrets-store-csi-driver/secrets-store-csi-driver --namespace kube-system

kubectl apply -f https://raw.githubusercontent.com/aws/secrets-store-csi-driver-provider-aws/main/deployment/aws-provider-installer.yaml
```

### Install Cert Manager ClusterIssuer

```bash
cd ./infra/helm/cert-manager
kubectl apply -f cluster-issuer.yaml
```

### Install Cluster Autoscaler

```bash
cd ./infra/helm/cluster-autoscaler
helm repo add autoscaler https://kubernetes.github.io/autoscaler
helm repo update

helm install cluster-autoscaler autoscaler/cluster-autoscaler   --set 'autoDiscovery.clusterName'=weatherapp-db-cluster   --set awsRegion=us-west-2
```

## Application

A basic .NET 8 API connected to PostgreSQL.

### Endpoints

GET /weatherforecast
- Public
- Reads the 10 latest weather records from a read replica of the DB

POST /weatherforecast
- Public
- Inserts a new record into the writer DB

Example body:
```json
{
  "temperatureC": 25,
  "summary": "Sunny"
}
```

## Application Deployment

### Docker
- Uses official Microsoft .NET 8 images.
- Building and storing Docker images in a private registry (e.g., Artifactory) is assumed and recommended.

### Helm Charts
Helm manages all Kubernetes manifests with templating support. Environment-specific values can be injected via values.yaml.

### Kubernetes Manifests

| File | Description |
|------|-------------|
| db-init-configmap.yaml | SQL schema definition as a config map |
| db-init-job.yaml | Initializes DB using a one-time psql job |
| deployment.yaml | Deploys app pods with readiness/liveness probes and secret mounts |
| hpa.yaml | Adds CPU-based Horizontal Pod Autoscaler |
| ingress.yaml | Exposes service using TLS via Cert Manager |
| secretproviderclass.yaml | Binds AWS Secrets Manager to Kubernetes |
| service.yaml | Internal networking access to the app |

### Deploying
```bash
cd ./app/helm
helm upgrade weather-app -f values.yaml --install .
```
